# スマホ対応（フェーズ3・第1弾実装）

客先要望の「データのモバイル化」に対する提案実装。**アプリストアのネイティブアプリ
ではなく、ブラウザのモバイル専用画面**とする。`develop` から分岐したブランチに
第1弾を実装した。**仕様は未確定**で、客先レビューを経て調整する前提。

- 画面: `/m`（受信箱）、`/m/parts/:id`（部品詳細）
- ログイン: 既存画面をそのまま使い、狭い幅向けの調整だけ追加
- 追加 API・追加テーブル: **なし**（第1弾）

---

## 1. なぜ PC 画面の流用ではなく専用ルートか

部品一覧は11列のテーブルを前提にしている。列を落とさずスマホに載せると横スクロール
になり、現場で片手で見る用途に耐えない。列を落とすと PC 側の運用と食い違う。

そこで `/m` 配下に専用ルートを新設し、一覧を**メールアプリのようなカード一覧**に
置き換えた。PC 画面のコンポーネントには手を入れていないので、PC 側の挙動は変わらない。

マスタ・データ取込・担当者の各画面は `/m` に出さない。これらは腰を据えて操作する
画面で、スマホで扱う想定がないため。

## 2. 画面

### 2.1 受信箱 `/m`

| 要素 | 内容 |
|---|---|
| 並び | 優先度順（色 → バッファの小さい順 → 滞留の長い順 → OS_ID） |
| タブ | すべて／要対応／困りごと。件数バッジ付き |
| 絞り込み | 担当者・機種 |
| 検索 | 部品名・部品番号・OS_ID・機種の部分一致 |
| 初期表示 | 非管理者は自分の担当。管理者はすべて |

**要対応**は「色が緑以外」または「滞留がしきい値以上」。今日手を打つべきかを1つの
条件に寄せ、1タップで絞り込めるようにしている。

カードに出す項目は、色・バッファ・残日数・機種・名称・部品番号・現工程・滞留・
困りごと印。保留（無期限）の部品は PC 側の運用と同じく受信箱から外す。

### 2.2 部品詳細 `/m/parts/:id`

上から工程 → 判定根拠 → 困りごと → メモの順。操作は親指の届く下端に固定する。

工程は縦カードで積む。工程数が30を超える部品があり、先頭の完了分をそのまま並べると
「いまどこにいるか」が画面外に押し出されるため、**先頭の完了工程は既定で畳む**
（「完了した N 工程を表示」で開く）。完了が2件以下なら畳まない。

### 2.3 ログイン

画面は増やさず、幅 640px 以下の調整だけ追加した。入力欄は 16px 未満にすると iOS が
自動ズームするため、フォントサイズと最小タップ高さを指定している。

---

## 3. 操作の考え方

客先イメージは「左右スワイプで消化していく」こと。第1弾ではスワイプは入れず、
同じ操作をボタンで置いた。判定の妥当性を先に確かめるためで、スワイプは第2弾で足す。

| 操作 | 意味 | 第1弾の実装 |
|---|---|---|
| 右スワイプ（緑） | 今日は確認した。その日の受信箱から消える | カード下部・詳細下部のボタン |
| 左スワイプ（橙） | 困りごとを立てる | 同上（既存の困りごとフラグ） |
| タップ | 詳細へ入る | カード本体のタップ |

### 3.1 「確認済み」は保留とは別物

既存の**保留は無期限**で、一覧から恒久的に外すためのもの。「今日は確認した」は
その日だけ消えて翌稼働日には戻ってくる。目的が違うので流用しない。

第1弾では**端末内（localStorage）にのみ**保持し、既定で**翌稼働日の朝6時**まで
受信箱から隠す。土日は稼働日として数えない（金曜に確認すると月曜の朝まで持つ）。
祝日カレンダーはサーバー側マスタにしか無いため、第1弾では土日のみ考慮している。

### 3.2 元に戻す

誤操作対策として、確定後 12 秒間「元に戻す」を画面下部に出す。手袋・片手操作で
押し直す余裕を見て長めに取った。

## 4. サーバー側

第1弾は**追加なし**。既存の以下をそのまま使う。

| 用途 | エンドポイント |
|---|---|
| 一覧 | `GET /api/parts` |
| 工程 | `GET /api/parts/timelines?ids=` |
| 基準日・担当者・しきい値 | `GET /api/meta` |
| 困りごと ON/OFF | `POST /api/parts/:id/trouble` |
| 困りごとメモ | `POST /api/parts/:id/memo` |
| 対応メモ | `POST /api/parts/:id/note` |
| 認証 | 既存の Cookie 認証 |

### 4.1 併せて直した既存の不具合

`GET /api/parts` はプロセス内キャッシュを持ち、そのキーが**再計算日時**だったため、
画面からの書込み（担当者・困りごと・保留・メモ）でキャッシュが外れなかった。
PC 画面は楽観更新で結果を先に描くので表面化しにくかったが、再読込の多いスマホでは
「困りごとを立てたのに戻ってくると消えている」という形で出る。書込み後に一覧
キャッシュを捨てるようにした（工程は変わらないのでキャッシュに残す）。

---

## 5. PC 画面との行き来

- 幅 640px 以下の端末が `/` か `/parts` を開いたときだけ `/m` へ送る。PC の他画面を
  開いている最中は横取りしない
- スマホ画面の「PC版」／PC 画面の「スマホ版」で切り替えられる。選んだ側は
  `localStorage`（`mop_view`）に覚えるので、次回から自動で戻される

---

## 6. 第2弾に回したもの

| 項目 | 内容 |
|---|---|
| 確認済みのサーバー保存 | 部品・ユーザー・期限を持つテーブルを追加。既定は翌稼働日の朝まで。端末をまたいでも同じ状態になる |
| 左右スワイプ | 右＝今日は確認した（緑）、左＝困りごと（橙） |
| 困りごとテンプレ | 材料未入荷・前工程遅れ・外注戻り遅れなど。管理者が PC のマスタ画面から編集。入力を速くするだけでなく、あとで分類集計できるようにするため |

祝日を含めた稼働日判定は、確認済みをサーバー保存する第2弾で `m_calendar` を使って
正しく計算する。

### 範囲外（当面やらない）

- PWA 化
- 圏外での閲覧
- 工場向けのログイン期限調整
