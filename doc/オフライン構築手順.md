# オフライン構築手順（先方・AWS 検証共通）

先方 Windows Server は **インターネットに出られない**。一時開放も不可。  
受け渡しは **Box**。GitHub / Git / Chocolatey / `npm ci` は先方では使わない。

Desktop Experience 付きでも Server Core（デスクトップ無し）でも同じスクリプトで構築する。  
Core のときは IIS 管理画面を入れず、画面確認は **別 PC のブラウザ** から `http://<サーバー>/` を開く。

検証も同じキット・同じスクリプトで箱から組み立てる。オンラインの `setup-server.ps1` で検証すると、先方と同じ手順の確認にならない。

---

## 役割

| | 何をするか | インターネット |
|--|--|--|
| ビルド用 Windows EC2 | キットを作る | 使う |
| AWS 検証 | キットだけで初回構築して確認 | 使わない |
| 先方 | 同じキットで初回構築 | 使わない |

キットには、以前オンラインで取っていた **インストーラ** と、`npm ci` 済みの **完成品**（`node_modules` / `dist` / Prisma エンジン）が入る。

---

## 1. ビルド用 EC2 でキットを作る

Windows Server（外に出られる、検証サーバーとは別）。リポジトリを clone して:

```powershell
cd C:\apps\mhi-app\app\deploy
.\make-offline-kit.ps1
# → dist-release\mhi-app-offline-YYYYMMDD.zip
```

所要は `npm ci` とインストーラ取得のため十数分かかることがある。  
ZIP は数百 MB〜1 GB 程度。

インストーラ取得だけ失敗した場合は、`installers\` にファイルを置いて `-SkipDownload` で再実行できる。

---

## 2. 検証 → 先方

同じ ZIP を使う。

1. AWS 検証サーバーへコピーし、§3 で箱から構築して画面確認
2. 問題なければ **同じ ZIP を Box に上げて先方へ**
3. 先方でも §3 を実行

---

## 3. 初回構築（検証・先方）

管理者 PowerShell:

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
# ZIP を展開（例: C:\Temp\mhi-app-offline-YYYYMMDD）
cd C:\Temp\mhi-app-offline-YYYYMMDD
.\setup-offline.ps1
```

`setup-offline.ps1` が行うこと:

- 同梱 MSI/EXE から Node.js 20 / PostgreSQL 18 / NSSM / URL Rewrite / ARR を入れる
- IIS を Windows の機能追加で有効化（ダウンロードしない）
- 完成品を `C:\apps\mhi-app` に配置
- `.env` 生成、DB `mop` 作成、Windows Service / IIS 登録
- `deploy.ps1 -SkipNpm -FirstRun`（migrate / seed / ETL。`npm ci` なし）

表示された PostgreSQL パスワードと Basic 認証は控える。

ブラウザで `http://<サーバー>/` → `/setup` で管理者作成。  
（Core の場合はサーバー上ではなく、自分の PC のブラウザから開く。）

IIS の Welcome 画面が出る場合:

```powershell
Import-Module WebAdministration
Stop-Website -Name "Default Web Site"
Start-Website -Name "MhiApp"
```

本番の `.env` は従来どおり `CSV_DIR` を共有フォルダへ。`AS_OF` 行は削除。変更後:

```powershell
Restart-Service MhiProgressApi
```

---

## 4. アップデート

ビルド用 EC2 で新しいオフライン ZIP を作り、Box で渡す。

```powershell
Copy-Item C:\apps\mhi-app\app\backend\.env C:\apps\backend.env.backup -Force
# 新 ZIP を展開
cd C:\Temp\mhi-app-offline-YYYYMMDD
.\deploy-offline.ps1
Get-Content C:\apps\mhi-app\RELEASE.txt
```

`.env` の退避と復元、完成品の上書き、migrate、IIS 配置、Service 再起動まで行う。`npm ci` はしない。

---

## 5. オンライン手順との違い

| | オンライン（旧） | オフライン（先方） |
|--|--|--|
| 作成 | `make-release.sh`（ソースのみ） | `make-offline-kit.ps1`（インストーラ + 完成品） |
| 作成場所 | Mac 可 | **Windows 必須** |
| 初回 | `setup-server.ps1`（Chocolatey / npm） | `setup-offline.ps1` |
| 更新 | ソース上書き + `deploy.ps1` | `deploy-offline.ps1` |
| 受け渡し | USB 等 | **Box** |

インターネットがある検証機だけで使う場合は、従来の `setup-server.ps1` も残してある。先方と同じ確認をするならオフラインキットを使う。

---

## 6. トラブルシュート

| 症状 | 対処 |
|------|------|
| `make-offline-kit` で PostgreSQL の取得失敗 | 公式 Windows インストーラを `installers\postgresql-18-windows-x64.exe` に置いて `-SkipDownload` |
| `nssm.cc` が取れない | `nssm-2.24.zip` を同じ `installers\` に置く |
| `Install-WindowsFeature` 失敗 | 先方 OS イメージに IIS の機能ソースが無い。IT に機能追加用メディアを確認 |
| deploy 成功だが画面が古い | 新しいキットで `deploy-offline.ps1` したか / `RELEASE.txt` |
| 502 / API 不通 | `Get-Service MhiProgressApi` / `C:\apps\mhi-app\logs\api.err.log` |
| `.env` が消えた | 更新前に `C:\apps\backend.env.backup` へ退避（`deploy-offline.ps1` は自動でやる） |
