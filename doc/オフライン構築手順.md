# オフライン構築手順（先方本番）

先方 Windows Server は **インターネットに出られない**（一時開放も不可）。  
GitHub / Git / Chocolatey / `npm ci` は先方では使わない。受け渡しは **Box**。

Desktop Experience（デスクトップあり）でも Server Core（デスクトップなし）でも、同じ ZIP・同じスクリプトで構築する。  
Core では IIS 管理画面を入れない。画面確認は **別 PC のブラウザ** から `http://<サーバー>/` を開く。

**持ち込み当日の手順**
- **先方 PC で作業**（Mac を社内 LAN に繋げない）→ [先方現地構築手順_先方PC作業.md](./先方現地構築手順_先方PC作業.md)
- **Mac を社内 LAN に繋いで RDP** → [先方現地構築手順.md](./先方現地構築手順.md)

---

## 全体の流れ

```text
① ビルド用 Windows（外に出られる・Base）
      fix-ps1-encoding.ps1
      make-offline-kit.ps1
              ↓
      mhi-app-offline-YYYYMMDD.zip
              ↓
② AWS 検証 Windows（外向きなし・できれば Core）
      展開 → setup-offline.ps1 → ブラウザ確認
              ↓ 同じ ZIP
③ Box → 先方
      展開 → setup-offline.ps1
```

**同じ ZIP を先方へ持っていく。** ただし「ビルド機で ZIP ができた」だけでは足りない。  
外に出られないサーバーで `setup-offline.ps1` が通ってから渡す。

---

## 役割と AWS の立て方

| | ビルド用 | 検証用（先方の真似） |
|--|--|--|
| 名前の例 | `MHI-build` | `MHI-offline-verify` |
| AMI | **Windows Server 2025 Base** | **Windows Server 2025 Core**（先方が Core なら） |
| インターネット | **あり** | **なし**（SG のアウトバウンドを全部閉じる） |
| ディスク | **50 GB**（30 GB は不可） | 50 GB |
| インスタンス | t3.medium | t3.medium |
| RDP | 自分の IP のみ | 自分の IP のみ |
| HTTP 80 | 不要 | 自分の IP のみ（画面確認用） |

1 台でビルドとオフライン検証は兼ねない。

検証機は外向きを閉じると Box からも落とせない。ZIP は Mac から RDP でコピーする。先方も同じ（Box は人が受け取り、サーバーへ持っていく）。

### RDP パスワード（AWS）

1. EC2 → インスタンス → 対象を選択
2. 状態が **実行中**、ステータスチェック完了まで待つ
3. **接続** → **Windows パスワードを取得**
4. 起動時の **`.pem` をアップロード** → **パスワードを復号化**
5. ユーザー名 `Administrator`、PC 名はパブリック IPv4

Mac からは Windows App（Remote Desktop）で接続する。

## 1. ビルド用：キットを作る

管理者 PowerShell（スタートで Windows PowerShell → 右の **Run as administrator**）。

Git が無い場合:

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
winget install --id Git.Git -e --source winget --accept-package-agreements --accept-source-agreements
```

**PowerShell を閉じて、管理者で開き直す**（入れた直後は `git` が見えない）。

```powershell
mkdir C:\apps -Force
cd C:\apps
git clone -b main https://github.com/sakaguchi-kolors/mhi-app.git
cd C:\apps\mhi-app\app\deploy
.\fix-ps1-encoding.ps1
.\make-offline-kit.ps1
```

`fix-ps1-encoding.ps1` は必須。Windows PowerShell 5.1 は UTF-8 の日本語スクリプトを壊して読む。これをやらないと `Unexpected token 'Download'` で落ちる。

成功の印はこれだけ:

```text
==> Created: C:\apps\mhi-app\dist-release\mhi-app-offline-YYYYMMDD.zip
```

フォルダ `dist-release\mhi-app-offline-YYYYMMDD` があるだけでは未完了。ZIP ができるまで閉じない。

途中で止まったら:

```powershell
dir C:\apps\mhi-app\dist-release
dir C:\apps\mhi-app\dist-release\mhi-app-offline-20260818\installers
# サイズが極端に小さい MSI は消してから make-offline-kit.ps1 を再実行
```

所要約十数分。ZIP は数百 MB〜1 GB。

## 2. 検証用：オフラインで箱から構築

ビルド機でできた **同じ ZIP** を、検証用（外向きなし）へ RDP コピーする。

管理者 PowerShell:

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
mkdir C:\apps\kit -Force
# make-offline-kit.ps1 の ZIP は tar で作成。Expand-Archive は Server Core で失敗する。
tar -xf C:\apps\kit.zip -C C:\apps\kit
cd C:\apps\kit\mhi-app-offline-YYYYMMDD
.\setup-offline.ps1
```

`setup-offline.ps1` が行うこと:

- 同梱インストーラから Node.js 20 / PostgreSQL 18 / NSSM / URL Rewrite / ARR を入れる
- IIS を Windows の機能追加で有効化（ネットに出ない）
- 完成品を `C:\apps\mhi-app` に配置
- `.env`・DB `mop`・Windows Service・IIS を作る
- migrate / ETL / seed / recompute（`npm ci` なし。20260818 キットは ETL→seed の順が逆のため、下記「初回 DB 補完」が別途必要）

表示された PostgreSQL パスワードと Basic 認証は控える。

**初回 DB 補完（必須・構築時 1 回だけ）**

20260818 キットの `setup-offline.ps1` では seed が ETL より先のため、`m_param`（`SHOP_LT_DAYS` 等）と `m_milestone`（検査 ◎）が欠ける。初回構築直後に 1 回実行する。**以降の運用・CSV 更新・アプリ更新では不要**（DB 作り直し時のみ再実行）。

```powershell
cd C:\apps\mhi-app\app\deploy
.\ensure-m-param.ps1

cd C:\apps\mhi-app\app\backend
npm run seed
npm run recompute
```

> 日本語入り SQL を PowerShell に直接貼らない（`description` が `????` になる）。

確認:

- `SHOP_LT_DAYS` / `BUFFER_GREEN` 等が `m_param` にあること
- 中間マイルストン定義で検査系に ◎ が **多数** 付いていること
- 部品詳細に `▼検査 期日MM/DD` が出ること
- パラメータ設定で値を変更して保存できること

確認:

- 自分の PC のブラウザで `http://<検証サーバーのIP>/`
- `/setup` で管理者アカウント作成
- 部品一覧が出ること

IIS の Welcome 画面が出る場合:

```powershell
Import-Module WebAdministration
Stop-Website -Name "Default Web Site"
Start-Website -Name "MhiApp"
```

ここで通った ZIP を、そのまま先方へ渡す。

## 7. Box へのファイルアップロード運用

先方サーバーはインターネットに出られない。**Box は「人がファイルを受け取る場所」** であり、サーバーが Box から直接ダウンロードする想定ではない。

### 7-1. 開発側（Mac）が Box に上げる

1. ビルド EC2 で ZIP のサイズ・ハッシュを確認:

```powershell
dir C:\apps\mhi-app\dist-release\mhi-app-offline-YYYYMMDD.zip
Get-FileHash C:\apps\mhi-app\dist-release\mhi-app-offline-YYYYMMDD.zip -Algorithm SHA256
```

2. Mac へ取得（例: ビルド EC2 で一時 HTTP 配信 + Mac から curl）:

```bash
curl -L -o ~/Downloads/mhi-app-offline-YYYYMMDD.zip "http://<ビルドEC2のIP>:8080/kit.zip"
ls -lh ~/Downloads/mhi-app-offline-YYYYMMDD.zip
shasum -a 256 ~/Downloads/mhi-app-offline-YYYYMMDD.zip
```

3. **Box** に `mhi-app-offline-YYYYMMDD.zip` をアップロード
4. 共有リンクまたはフォルダを先方 IT に渡す（ダウンロード権限付き）
5. **USB にも同じ ZIP を入れておく**（Box 不可・遅い場合の保険）

### 7-2. 先方 IT がサーバーへ置く

```text
Box（社内 PC でダウンロード）
    ↓ USB または社内ファイル共有
先方 Windows Server（C:\apps\kit.zip など）
    ↓ tar -xf
setup-offline.ps1
```

先方サーバー自身は Box にアクセスしない。

### 7-3. 先方へ渡す情報（メモ例）

| 項目 | 内容 |
|------|------|
| ファイル名 | `mhi-app-offline-YYYYMMDD.zip` |
| サイズ | 約 540 MB |
| SHA256 | ビルド機で確認した値 |
| 展開 | `tar -xf <ZIP> -C C:\apps\kit`（**Expand-Archive 禁止**） |
| 初回構築 | `cd C:\apps\kit\mhi-app-offline-YYYYMMDD` → `.\setup-offline.ps1` |
| 画面確認 | 別 PC のブラウザから `http://<サーバー>/` |

## 8. CSV 取込（先方本番運用）

### 8-1. 必要な CSV（4 ファイル・名前固定）

| ファイル名 |
|-----------|
| `FLEXSCHE結果出力5(残工程数見直し).csv` |
| `OCTPuS工程実績.csv` |
| `PBS部品計画納期リスト.csv` |
| `SHOP_JOBマスタ.csv` |

### 8-2. 初回構築後

1. IT が **共有フォルダ**（例: `C:\share\csv` または `\\fileserver\share\csv`）を用意
2. 社内システム or IT が 4 CSV をそのフォルダに配置
3. `.env` を編集:

```env
CSV_DIR=C:/share/csv
```

（UNC の場合は `CSV_DIR=\\fileserver\share\csv`）

4. `AS_OF` 行は **削除**（実行日になる）
5. API 再起動:

```powershell
Restart-Service MhiProgressApi
```

6. ブラウザ → 管理者モード → **データ取込** → 4 ファイル OK → **取込実行**

### 8-3. 日常運用

- **定期**: 管理者画面「データ取込」の **自動取込** を有効にし、時刻（例: 08:00 と 13:00、日本時間）を指定する。API サービス（`MhiProgressApi`）が動いていれば、指定時刻に `CSV_DIR` の 4 ファイルを取り込む。取込用のタスクスケジューラ追加は不要。
- ファイルが揃っていない時刻はスキップされる。手動の「取込実行」もそのまま使える。
- CSV を差し替えたあと ETL が走ると DB が更新される
- **DBバックアップ**: セットアップ／デプロイ時にタスク `MhiApp-BackupDb` を登録する。毎日 03:00 に `C:\apps\mhi-backup\<日付_時刻>\` へ `pg_dump`（担当・困りごと・マスタ等も含まれる）。60 日超は自動削除。保存先を別ディスクにする場合は `install-ops-tasks.ps1 -BackupRoot D:\mhi-backup`
- **ログローテート**: NSSM が API ログを約 24 時間ごとに切る。タスク `MhiApp-RotateLogs` が毎日 00:15 に API / IIS / PostgreSQL の 60 日超ログを削除する
- 手動実行: `Start-ScheduledTask -TaskName MhiApp-BackupDb` / `MhiApp-RotateLogs`
- リストア例（停止してから）:

```powershell
Stop-Service MhiProgressApi
$env:PGPASSWORD = '<mopのパスワード>'
& "C:\Program Files\PostgreSQL\18\bin\pg_restore.exe" -h localhost -U mop -d mop --clean --if-exists C:\apps\mhi-backup\<フォルダ>\mop.dump
Copy-Item C:\apps\mhi-backup\<フォルダ>\backend.env C:\apps\mhi-app\app\backend\.env -Force
Copy-Item C:\apps\mhi-backup\<フォルダ>\ingest-schedule.json C:\apps\mhi-app\app\backend\data\ingest-schedule.json -Force
Restart-Service MhiProgressApi
```

### 8-4. AWS 検証で CSV を試す場合（参考）

本番では IT が共有フォルダに置く。AWS 検証のみ Mac から RDP フォルダ共有で運ぶ:

- Windows App → Folders → **`~/teikyo-csv`**（ASCII 名推奨。日本語フォルダ名はパス文字化けしやすい）
- 検証 EC2: `net use` で `\\tsclient\teikyo-csv` を確認 → `C:\share\csv` にコピー
- **`dir \\tsclient\` は空でもよい**（フォルダ単位リダイレクトではルート一覧不可）

## 9. トラブルシュート

| 症状 | 対処 |
|------|------|
| `Expand-Archive` で大量エラー | **`tar -xf` で展開**（`Expand-Archive` は使わない） |
| `tar -xf` でも ZIP decompression failed | ZIP が壊れている。ビルド機で作り直し。転送後は `Get-FileHash` で一致確認 |
| `dir \\tsclient\` が無い | `net use` を確認。フォルダリダイレクトなら `\\tsclient\<フォルダ名>` は出る |
| 日本語フォルダ名で Copy-Item 失敗 | Mac 側フォルダを ASCII 名（`teikyo-csv`）にして RDP 再接続 |
| `Unexpected token 'Download'` | `.\fix-ps1-encoding.ps1` を先に実行 |
| `git` が認識されない | Git 導入後に PowerShell を開き直す。または `$env:Path` を Machine+User で入れ直す |
| `winget` が msstore で証明書エラー | `--source winget` を付ける |
| ZIP が無くフォルダだけ | 途中終了。`Created:` が出るまで再実行。欠けた MSI は消す |
| 30 GB でディスク不足 | 50 GB で立て直す |
| PostgreSQL インストーラ取得失敗 | `installers\postgresql-18-windows-x64.exe` を置いて `-SkipDownload` |
| `nssm.cc` が取れない | `nssm-2.24.zip` を `installers\` に置く |
| `Install-WindowsFeature` 失敗 | OS イメージに IIS の機能ソースが無い。先方 IT に確認 |
| 502 / API 不通 | `Get-Service MhiProgressApi` / `C:\apps\mhi-app\logs\api.err.log` |
| バックアップが無い | `Get-ScheduledTask MhiApp-BackupDb`。未登録なら `cd C:\apps\mhi-app\app\deploy; .\install-ops-tasks.ps1` |
| ログが肥大 | `C:\apps\mhi-app\logs` と `Get-ScheduledTask MhiApp-RotateLogs`。NSSM の `AppRotateSeconds` が 86400 か |
| `.env` が消えた | `deploy-offline.ps1` は自動退避する。手作業更新なら先に `C:\apps\backend.env.backup` へコピー |
