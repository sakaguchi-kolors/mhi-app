# 開発・検証・デプロイ手順

## 1. 全体構成

```text
Mac（ローカル開発）
        │
        ▼
（社内）Git / GitHub — 開発側のバージョン管理のみ
        │
        ▼
make-release.sh → 納品 ZIP
        │
        ├──────────────────────────────┐
        ▼                              ▼
AWS Windows Server（検証）      先方 Windows Server（本番）
  IIS + NestJS + PostgreSQL       同左（GitHub 非利用）
        │                              │
        ▼                              ▼
https://dev.example.com           社内 URL
（Basic認証 + アプリログイン）
```

認証は **AD 不要**。検証・本番ともに **アプリ内ログイン（JWT）** を使用します。  
IIS Basic 認証は URL ゲート（関係者以外のアクセス遮断）のみ。

> **先方本番**は GitHub / Git を使わず、インターネットにも出られない。  
> 先方と同じ確認をするなら [オフライン構築手順.md](./オフライン構築手順.md) のキットで検証サーバーも構築する。  
> インターネットありの従来手順は [WindowsServerデプロイ手順.md](./WindowsServerデプロイ手順.md)。

## 2. AWS EC2 起動設定

| 項目 | 推奨値 |
|------|--------|
| OS | Windows Server 2022 Base |
| インスタンス | t3.medium（CSV 大量 ETL なら t3.large） |
| ストレージ | 50 GiB gp3/gp2 |
| パブリック IP | 有効 |
| セキュリティグループ | 80, 443 公開 / **RDP(3389) は自 IP のみ** |

起動後 **Elastic IP** を割り当て（IP 固定化）。

## 3. 初回セットアップ（EC2 上）

RDP で Windows Server にログインし、**管理者 PowerShell** で実行。

### 3-1. ソース配置

**推奨: 納品 ZIP（本番と同じ手順）**

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
mkdir C:\apps -Force
Expand-Archive -Path C:\Temp\mhi-app-release-YYYYMMDD.zip -DestinationPath C:\Temp\release -Force
Move-Item C:\Temp\release\staging-mhi-app C:\apps\mhi-app -Force
cd C:\apps\mhi-app\app\deploy
.\setup-server.ps1
```

**社内で Git clone する場合（検証環境のみ）**

```powershell
cd C:\apps
git clone <リポジトリURL> mhi-app
cd mhi-app\app\deploy
.\setup-server.ps1 -InstallGit -RepoUrl "<リポジトリURL>"
```

### 3-2. setup-server.ps1 が行うこと

- Node.js 20 / PostgreSQL 18 / NSSM インストール（Git は `-InstallGit` 時のみ）
- IIS + URL Rewrite + ARR 設定
- PostgreSQL DB（`mop`）作成
- `backend/.env` 生成（JWT_SECRET 自動生成）
- Windows Service `MhiProgressApi` 登録
- IIS サイト `MhiApp` 作成（`C:\inetpub\mhi`）
- IIS Basic 認証（パスワードは未指定時ランダム生成。コンソール出力を控える）
- 初回デプロイ（build + migrate + etl + seed + recompute）。20260818 キットは `setup-offline` 後に Step 13.5（`ensure-m-param` + seed + recompute）が別途必要

## 4. 動作確認

1. ブラウザで `http://<Elastic-IP>/` にアクセス
2. IIS Basic 認証（`mhi` / setup 時に表示されたパスワード）
3. 初回は `/setup` で管理者アカウント作成
4. ログイン後、部品一覧・マスタ等を確認

API 単体確認（RDP 内）:

```powershell
Invoke-RestMethod http://127.0.0.1:8787/api/health
Invoke-RestMethod http://127.0.0.1:8787/api/auth/setup
```

## 5. 2 回目以降のデプロイ

### 納品 ZIP で更新（本番と同じ）

```powershell
Copy-Item C:\apps\mhi-app\app\backend\.env C:\apps\backend.env.backup -Force
# 新 ZIP を展開して C:\apps\mhi-app\ を上書き
Copy-Item C:\apps\backend.env.backup C:\apps\mhi-app\app\backend\.env -Force
cd C:\apps\mhi-app\app\deploy
.\deploy.ps1
Get-Content C:\apps\mhi-app\RELEASE.txt
```

### 社内 Git 環境の場合

```powershell
cd C:\apps\mhi-app\app\deploy
.\deploy.ps1 -GitPull
```

処理内容:

```text
（既定）ディスク上のソースをビルド
  → backend/frontend: npm ci → build（Service 稼働中）
  → Windows Service 停止
  → prisma migrate deploy
  → frontend/dist を IIS へ配置
  → Service 再起動 → ヘルスチェック
```

### 反映確認

```powershell
Get-Content C:\apps\mhi-app\RELEASE.txt
dir C:\inetpub\mhi\assets\index-*.js
```

## 6. HTTPS 化（任意・推奨）

1. ドメインの A レコードを Elastic IP に向ける
2. IIS に SSL 証明書を設定（Let's Encrypt win-acme 等）
3. `backend/.env` で `COOKIE_SECURE=true` に変更
4. Service 再起動: `Restart-Service MhiProgressApi`

## 7. ディレクトリ構成（サーバー）

```text
C:\apps\mhi-app\
  RELEASE.txt         納品バージョン
  app\
    backend\          NestJS ソース + .env
    frontend\         React ソース
    deploy\           deploy.ps1 / setup-server.ps1 / make-release.*
    sample-data\      サンプル CSV
  data\csv\           取込元 CSV（検証用）
  logs\               API ログ（NSSM が約24時間で切る。60日超は削除）

C:\apps\mhi-backup\   DBバックアップ（毎日 03:00、60日保持）
C:\inetpub\mhi\       IIS 配信（frontend/dist + web.config）
```

## 8. トラブルシュート

| 症状 | 確認 |
|------|------|
| deploy 成功したが画面が古い | ソース上書きしたか / `RELEASE.txt` / `index-*.js` ハッシュ |
| `npm EPERM ... query_engine-windows.dll.node` | `Stop-Service MhiProgressApi -Force` してから `deploy.ps1` |
| 502 / API 不通 | `Get-Service MhiProgressApi` / `C:\apps\mhi-app\logs\api.err.log` |
| DB 接続エラー | `backend\.env` の DATABASE_URL / PostgreSQL サービス |
| 画面真っ白 / IIS Welcome | `Stop-Website "Default Web Site"` → `Start-Website "MhiApp"` |
| /api 404 | URL Rewrite + ARR が入っているか、ARR プロキシ有効か |
| Cookie ログイン不可 | HTTPS 化後は `COOKIE_SECURE=true` |

## 9. 本番（先方 Windows Server）への移行

詳細は **[WindowsServerデプロイ手順.md](./WindowsServerデプロイ手順.md)** を参照。

AWS 検証で確認済みの **同じ納品 ZIP + deploy.ps1** を先方へ受け渡します。

先方環境での差分確認:

- `.env`（DB 接続、CSV パス、JWT_SECRET）
- IIS Basic 認証の要否（社内 VPN 内のみなら省略可）
- HTTPS 証明書
- 自動取込（データ取込画面で時刻指定。既定例 08:00 / 13:00）

## 開発フローまとめ

```text
Mac で開発 → ローカル確認
    ↓
make-release.sh で納品 ZIP 作成
    ↓
AWS: ZIP 配置 → deploy.ps1 → 確認
    ↓
Basic 認証 URL でレビュー → 修正
    ↓
同じ ZIP を先方 Windows Server へ受け渡し → deploy.ps1
```
