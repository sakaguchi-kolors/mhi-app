# モックとの違い

モック（`moc/`）は **機能検証用のプロトタイプ** です。  
現行（`app/`）は、モックで固まった算出・画面・API契約を踏襲しつつ、**本番運用向けの技術構成へ置き換えたもの**です。

## 比較一覧


| 項目         | モック                       | 現行（本番向け）                  | 変更有無        |
| ---------- | ------------------------- | ------------------------- | ----------- |
| フロントエンド    | React + TypeScript (Vite) | React + TypeScript (Vite) | 維持          |
| ランタイム      | Node.js + TypeScript      | Node.js + TypeScript      | 維持          |
| APIフレームワーク | Express（単一サーバ）            | NestJS（モジュール分割）           | **変更**      |
| DBアクセス     | 生SQL（`schema.sql`）        | Prisma（ORM + Migration）   | **変更**      |
| データベース     | PostgreSQL                | PostgreSQL                | 維持          |
| 認証         | 管理者モードのトグル中心              | ログイン＋権限管理                 | **強化**      |
| Webサーバー    | ローカルは Node が静的配信          | IIS（本番）                   | **本番向けに追加** |
| アプリ常駐      | 開発時は手動起動                  | Windows Service           | **本番向けに追加** |
| データフロー・算出  | CSV → ETL＋算出 → 一覧表示       | 同左                        | 維持          |




## 変えたもの／変えなかったもの



### 維持したもの（選定理由）

- **React + TypeScript**  
モックで画面・操作感が検証済みのため、作り直しコストを避けて継続。
- **Node.js + TypeScript**  
Windows Server で動作し、フロントと言語を統一できるため継続。
- **PostgreSQL**  
大量CSV由来のデータにも耐える実績があり、モックでも採用済みのため継続。
- **算出ロジック・API契約・画面の基本機能**  
業務要件の核はモックで合意できているため、挙動は変えず土台だけ強化。



### 変更したもの（選定理由）



#### Express → NestJS


| 観点  | モック（Express）       | 現行（NestJS）         |
| --- | ------------------ | ------------------ |
| 向き  | プロトタイプ向き（素早く縦串を通す） | 本番・継続開発向き          |
| 構造  | 単一ファイル中心で拡張しにくい    | 機能単位のモジュール分割       |
| 保守  | 規模拡大で見通しが悪化しやすい    | DI・層分けでテスト・拡張がしやすい |


**選定理由**

- モックは「動くものを早く見せる」目的だったため Express で十分だった
- 本番では認証・権限・マスタ・取込・監査など機能が増えるため、構造化された NestJS が適する
- Rails 経験者にも理解しやすい MVC／DI の設計思想で、保守・引き継ぎしやすい



#### 生SQL → Prisma


| 観点   | モック（生SQL）        | 現行（Prisma）       |
| ---- | ---------------- | ---------------- |
| 向き   | スキーマを素早く試す       | 型安全に長期運用する       |
| 変更管理 | SQL手書き中心         | Migration で履歴管理  |
| 型    | 手作業で合わせやすいが漏れやすい | TypeScript と自動連携 |


**選定理由**

- 本番ではテーブル変更・環境差分が続くため、Migration 管理が必要
- TypeScript との親和性が高く、API〜DB まで型でつながる
- AI／開発ツールとの相性が良く、開発効率と品質を両立しやすい



#### 認証の強化・IIS / Windows Service の追加

**選定理由**

- モックは機能確認が主目的で、簡易な管理者切替で足りた
- 本番は利用者・管理者の権限分離と、Windows 標準運用（IIS・Service）が必要
- 先方 Windows Server 制約（Linux VM / Docker 不可）に合わせた納品形態にするため

# 技術選定理由



## フロントエンド



### React + TypeScript



### 概要

管理画面や利用者が操作する画面を構築するためのフレームワークです。

### 採用理由

- モックで画面・操作感を検証済みで、作り直しが不要
- コンポーネント単位で画面を分割でき、一覧・詳細・マスタなど画面追加に強い
- TypeScript により型安全にフロントを実装できる
- 静的ビルド成果物を IIS で配信でき、Windows Server 運用と相性が良い

---



## バックエンド



### Node.js



### 概要

JavaScript・TypeScriptをサーバー側で実行するための実行環境です。

### 採用理由

- Windows Serverで安定して動作する
- Linux環境に依存しない
- フロントエンドと同じTypeScriptを利用できる
- 将来的にLinux環境へ移行する場合も構成変更が少ない

---



### NestJS



### 概要

Node.js向けのWebアプリケーションフレームワークです。

RailsでいうRails本体に相当する役割を担います。

### 採用理由

- モックの Express から、本番向けの保守性・拡張性へ引き上げるため
- MVCアーキテクチャを採用しており保守しやすい
- DI（Dependency Injection）に対応しており大規模開発に向いている
- API開発との相性が良い
- Rails経験者でも理解しやすい設計思想

---



## データベース



### PostgreSQL



### 概要

システム内のデータを保存・管理するリレーショナルデータベースです。

### 採用理由

- 高い信頼性と実績がある
- 大量データにも強い（CSV取込・算出結果の保持に適する）
- オープンソースでライセンス費用が不要
- 業務システムとの相性が良い
- モック時点から採用しており、データモデルを継続利用できる

---



## ORM



### Prisma



### 概要

Node.jsからPostgreSQLを操作するためのORM（Object Relational Mapper）です。

SQLを直接大量に記述することなくデータベースを操作できます。

### 採用理由

- モックの生SQL運用から、型安全・Migration管理へ移行するため
- TypeScriptとの親和性が非常に高い
- Migration管理が容易
- 型安全なデータアクセスが可能
- AIによるコード生成との相性が良い

---



## Webサーバー



### IIS（Internet Information Services）



### 概要

Windows Server標準のWebサーバーです。

HTTPS通信の受付やWebアプリへのアクセスを中継します。

### 採用理由

- Windows Server標準機能のため追加ソフトウェアが不要
- Windows Serverとの親和性が高い
- SSL証明書の管理が容易
- 運用担当者が管理しやすい

役割イメージ

```
ブラウザ
    │
 HTTPS
    │
   IIS
 ├ React画面配信
 └ APIをNestJSへ転送
```

---



## アプリケーション常駐



### Windows Service



### 概要

NestJSアプリケーションをWindowsサービスとして常駐起動させます。

### 採用理由

- Windows起動時に自動起動できる
- サービス管理画面から停止・再起動できる
- ログインユーザーがいなくても動作する
- Windows Serverの標準運用に適している

# 今回この構成を採用する理由

今回のシステムは以下の条件があります。

- オンプレミスWindows Serverへ導入
- Linux VMの利用不可
- Docker(Linuxコンテナ)利用不可
- PostgreSQL利用

これらを踏まえ、Windows Server上で安定稼働し、保守性・拡張性・開発効率のバランスが最も良い構成として、

- React + TypeScript
- Node.js + NestJS
- PostgreSQL
- Prisma
- IIS

を採用します。

モックでは Express + 生SQL で機能検証を行い、現行ではその成果（算出・画面・API契約）を維持したまま、NestJS + Prisma へ移行しています。  
フロントエンド・バックエンドともにTypeScriptで統一することで、開発効率の向上と保守コストの削減を実現します。
